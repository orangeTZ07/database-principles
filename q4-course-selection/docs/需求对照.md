# 需求对照：第四题 选课管理系统

来源：《数据库课程设计题目-【功能精简版】》第四题。`DB` 列指数据库层（`sql/`）的实现，`应用` 列指 Flask 层（`app/`）。

## 角色与权限

| 题目要求 | 实现 |
| --- | --- |
| 系统管理员（admin）拥有全部功能 | `sql/05_reference_data.sql` 的 `role_permission`：admin 拥有全部功能键 |
| 教研科：制定专业培养方案 | `research` → `plan`（培养方案）+ `query` |
| 教务科：教学进程、教学任务、课程表、选课总况统计、数据挖掘 | `academic` → `progress / tasks / timetable / stats / mining / query` |
| 教师：数据查询 | `teacher` → `query` |
| 学生：选课、数据查询 | `student` → `enroll` + `query` |
| 权限控制 | `app/auth.py` 的 `require()` 装饰器按 `role_permission` 判定，无权限 403，未登录跳登录页；菜单随权限变化。矩阵见 `tests/test_auth.py::test_permission_matrix` |

## 1. 培养方案（教研科）

| 要求 | 实现 |
| --- | --- |
| 课程含先导课程 | DB：`course` + `course_prereq`（自关联）；触发器 `trg_prereq_acyclic` 禁止自环 / 循环依赖（递归 CTE）。应用：`app/views/plan.py` 的先导课程勾选页（先在应用层检查，再由触发器兜底） |
| 各专业各学期计划开课，含学时 / 学分 / 开课学院 | DB：`curriculum_plan(major_id, semester_no, course_id, hours, credits, college_id, nature)`，`uk_plan_major_course`、`CHECK` |
| 四年制，8 个学期 | `CHECK (semester_no BETWEEN 1 AND 8)`；页面上学期下拉为第 1~8 学期 |

## 2. 基础信息

| 要求 | 实现 |
| --- | --- |
| 学院 / 系、行政班、学生 | `org_unit`、`major`、`admin_class`、`student`；`app/views/basic.py` 通用增删改查（搜索、筛选、外键友好提示） |
| 教师，可上哪些课程 | `teacher` + `teacher_course`；页面 `basic.teacher_courses` 勾选 |
| 教室：教学区 / 多媒体 / 容量 | `classroom(area, building, room_no, floor, is_multimedia, capacity)` |

## 3. 教学进程计划

| 要求 | 实现 |
| --- | --- |
| 教务科录入学期，系统自动生成教学任务 | 应用：`academic.progress_home` 录入学期（教学日历周数、开学日期、选课窗口）；存储过程 `sp_generate_tasks`，一条 `INSERT … SELECT … ON DUPLICATE KEY UPDATE` 由「培养方案 × 班级」汇总出任务与必修人数，幂等 |
| 应在上学期期中前制定 | `progress` 页面计算截止时间 = 上学期开学日 + 周数/2，到期仍未生成显示「已逾期未制定」 |

## 4. 教学任务

| 要求 | 实现 |
| --- | --- |
| 课头拆分：必修课人数超过教室最大容量或班额限额时拆分 | `app/services/sections.py::split_task`：每班上限 = `min(班额限额 setting.section_limit, 教室最大容量)`，课头数 = ⌈人数 / 上限⌉，容量均摊；已有学生选课则禁止重新拆分。任选课按预计人数（预测或手工）拆。测试：`tests/test_flow.py::SectionSplitTests` |
| 教师分配：多人合上，仅一名主讲 | DB：`section_teacher`，`lead_key` 生成列 + 唯一索引保证每课头 ≤ 1 个主讲；触发器 `trg_section_teacher_qualified` 校验任课资格。应用：手工添加 / 设主讲 / 移除，也可「自动分配」（按本学期负载最轻者优先） |

## 5. 编制课程表

| 要求 | 实现 |
| --- | --- |
| 依据教学日历周数 | `term.weeks`；`schedule_slot.week_start/week_end`；触发器 `trg_slot_room_conflict` 拒绝超出周数的排课 |
| 解决冲突 | 应用 `Occupancy.conflicts`：教室 / 教师 / 班级 / 容量 / 周次 / 同课头重叠，提示具体冲突对象；DB 触发器再次兜底教室冲突；页面列出整个学期的冲突清单（`find_conflicts`） |
| 尽量保持教室不变；需变化则就近 | `auto_schedule_section`：同一课头第一块选容量最合适的空闲教室并作为「锚点」，后续时间块优先沿用锚点教室；锚点被占用时按 `room_distance`（教学区 → 教学楼 → 楼层 → 房间号）挑最近的空闲教室。测试：`tests/test_flow.py::SchedulerPolicyTests` |

## 6. 选课

| 要求 | 实现 |
| --- | --- |
| 学生看到下学期必修课程列表，选教学班 | `student.enroll_home`：必修课程（本班）+ 任选课程；`enroll_course` 页显示各教学班的教师、时间教室、剩余名额 |
| 有空位才成功，满员拒绝 | 存储过程 `sp_enroll`：事务 + `FOR UPDATE` 行锁 + 触发器 + `CHECK` 三重保证；并发测试 `tests/test_selection.py` |
| 自由选课时段内可退选 | `sp_drop`，窗口由 `term.select_start/select_end` 决定；窗口外选课 / 退选均被拒绝 |
| 其他规则（附加） | 必修课只能选本班课程；同课程只能选一个教学班（主键）；与已选课程时间冲突拒绝 |

## 7. 查询统计

| 要求 | 实现 |
| --- | --- |
| 培养方案查询 | `query.plan`：按专业分学期展示，含学分 / 学时合计、先导课程 |
| 选课综合查询（教学进程、教学任务、课表、名单） | `query.selection_query`，另有 `06_report_queries.sql` 的纯 SQL 版本 |
| 打印课表 | `query.student_timetable`（学生）/ `query.teacher_timetable`（教师），课表网格 + 课程清单，带「打印」按钮和打印样式 |
| 选课总况统计，含同比环比，图表 + 表格 | `stats.index`：班级、教师两个维度；数据来自视图 `v_class_term_stat` / `v_teacher_term_stat`，用窗口函数 `LAG()` 取上学期（环比）与去年同期（同比）并校验学期连续性；SVG 柱状图 + 表格切换，可打印。测试：`tests/test_analytics.py::StatisticsTests` |
| 数据挖掘：历年人数趋势预测 | `app/services/mining.py::linear_forecast`（最小二乘线性回归）+ 存储函数 `fn_forecast_enroll`（数据库内同算法），页面并排展示、交叉校验；折线图展示历史与预测 |
| 预测人数指导教室安排 | `mining.recommend`：按预测人数算课头数，再为每个课头人数推荐容量足够的最小教室（多媒体优先）；「采纳」写入 `course_forecast` 与教学任务预计人数，「采纳并拆分课头」直接拆课头 |

## 8. 用户管理

| 要求 | 实现 |
| --- | --- |
| admin 添加用户、停用 / 启用、复位密码 | `app/views/users.py`；admin 账号不可停用；停用后立即登录不上，已登录会话下一次请求即失效 |
| 修改密码须输入原密码 | `main.password`：校验原密码、新密码 ≥ 6 位、两次一致、不能与原密码相同 |
| 账号全英文、不重复 | DB：`app_user.username` 主键 `utf8mb4_0900_ai_ci`（大小写视为重复）+ `CHECK REGEXP_LIKE`；应用层先校验给出友好提示。测试：`tests/test_auth.py::UserManagementTests` |
| 初始密码 123，账号 admin | `run.py --no-seed` 只创建 `admin / 123`；种子数据所有账号初始密码均为 123；复位也是 123。密码以 PBKDF2-SHA256 加盐散列存储（`app_user.password_hash`），不存明文 |
